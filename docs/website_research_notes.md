# Portfolio Website Research Notes

These notes record the evidence behind the redesign so future edits do not drift back into generic portfolio copy.

## Design Decisions

- Recruiter-facing pages must support fast scanning. The Ladders 2018 eye-tracking update reported an average initial resume screen of 7.4 seconds and recommended clear layouts, bold role/title headers, and short declarative accomplishment statements.
- Web users scan when a page does not give them strong visual cues. Nielsen Norman Group recommends putting important points early, using visible headings, visually grouping related content, bolding important terms, using meaningful links, using bullets, and cutting unnecessary content.
- First impressions form very quickly. Tuch et al. found visual complexity and prototypicality affected perceived website aesthetics within 50 ms, and low visual complexity with high prototypicality was rated highly appealing.
- Visual polish matters, but it cannot rescue major usability problems. NN/g’s aesthetic-usability effect summary says attractive interfaces are perceived as more usable, while noting the effect is limited to minor issues.
- Credibility needs proof. Stanford’s web credibility guidelines emphasize verifiable information, visible expertise, clear contact information, professional design, usefulness/ease of use, recent updates, restraint, and avoiding errors.
- Accessibility and performance are part of recruiter polish. WCAG contrast guidance explains the 4.5:1 normal-text contrast ratio, and web.dev documents Core Web Vitals as LCP, INP, and CLS metrics surfaced by Google tools.

## Content Rules Used

- Put name, target roles, graduation, and core tools above the fold.
- Use measured project signals: UWB range extension, calibrated MAE, static-run sample counts/RMSE, Caterpillar rotations, GPA, and GoAERO prize.
- Keep proprietary Caterpillar work non-specific and public-safe.
- Separate source-backed facts from user-provided context and avoid unsupported numbers.
- Prefer four strong project stories over a long list of thin cards.
- Keep project pages structured as problem, role, implementation, result, and evidence.
